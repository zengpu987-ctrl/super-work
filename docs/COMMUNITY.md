# 社区与协作 / Community & Collaboration

## 1. 这个项目如何做到「人人可编辑共享」

GitHub 不允许匿名直接写入公共仓库；本项目的开放方式是**公共仓库 + 宽松许可证 + 低门槛贡献路径**：

1. **Fork**：任何人可复制仓库、自由修改与分发（Apache-2.0，保留 NOTICE）。
2. **Pull Request**：任何 GitHub 账号都可提议修改；文档、翻译、示例、Provider 适配都欢迎。
3. **GitHub Web 编辑器 / Codespaces**：无需本地环境，浏览器里改一行文档即可发起 PR（`.devcontainer/` 已配置）。
4. **Discussions**：提问、方案讨论、合作招募、Show & Tell。
5. **Wiki**：维护者与贡献者共同维护 FAQ、部署笔记、Provider 速查。
6. **权限升级**：持续贡献者可成为 reviewer/maintainer，获得直接写权限（见 `GOVERNANCE.md`）。

> 结论：不是「匿名随便改」，而是「任何有 GitHub 账号的人都能以最低摩擦提出修改，并被认真评审」。

## 2. 首次贡献路线

- 找 `good first issue` 或 `docs` 标签；
- 小修：GitHub 网页 → 编辑 → Create branch → PR；
- 大改：先开 Proposal issue，7 天讨论；
- PR 描述模板会要求：问题、方案、验证、截图、破坏性变更、许可证确认。

## 4. 合作目标（我们要一起实现什么）

1. **厂商中立的多模型编排协议**：可插拔 provider、可复现的编排语义。
2. **本地优先的隐私标准**：数据/凭证不出本机，审计可验证。
3. **通用产物交付**：文字、图片、3D、Office/PDF 文件都能可靠交付。
4. **可解释的成本与上下文**：每次调用可追溯、可预算。
5. **开放生态**：插件 SDK、评测基准、跨平台客户端。

## 5. 招募与联络

- 在 Discussions →「合作与招募」发帖：背景、可投入时间、想做的事；
- 或在 issue 上打 `collaboration` 标签；
- 厂商合作请披露所属关系，遵循厂商中立原则；
- 安全问题上走私密公告，不要公开。

## 6. 社区规范

参见 `CODE_OF_CONDUCT.md`。我们坚持对事不对人、尊重不同语言与经验水平、保护用户隐私。
